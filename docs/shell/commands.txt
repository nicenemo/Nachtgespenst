# The shell of the boards: one section per command ("== name"). This file is the single source of the manual:
# tools/Manual.java turns it into include/ShellHelp.h (the built-in help), docs/wiki/shell.md and site/shell.html, and it is the file help.txt
# on the SD card of the CoreS3 (jbang tools/Shell.java install-help): "help <command>" prints the section from the card, or the usage line without one.
# Lines in a section: "usage:", "summary:", then free text, "reply:" lines and "example:" lines. Commands and arguments are lower case.

== help
usage: help [command]
summary: List the commands, or explain one.
Without an argument the commands are listed with a one-line summary. With a command name the full text of that command is printed: from help.txt on the
SD card when there is one, otherwise the usage line and the summary that are built into the firmware.
reply: OK HELP, then the lines | ERR help unknown
example: help layer

== ping
usage: ping
summary: Check that the board answers.
reply: OK PONG
example: ping

== info
usage: info
summary: Board, name, firmware build time, screen size, number of pages.
The firmware build time (fw=) is the first thing to check before trusting a test: it tells which build is on the board.
reply: OK INFO board=S3 name=NG-S3 fw=Nov 19 2026_17:30:28 w=320 h=240 pages=30 locks=26
example: info

== state
usage: state
summary: The current page, the host lock LEDs, the last key, the connections.
Shows the page number and title, the Caps, Num and Scroll Lock state the host reports, the last key pressed, the number of presses, and whether USB and
Bluetooth are connected (conn, usb, ble).
reply: OK STATE page=0/30 title=Maven Tools caps=0 num=0 scroll=1 last=- presses=0 conn=1 usb=1 ble=1
example: state

== layer
usage: layer <n>
summary: Show page n (0 is the first key layer).
The pages are the key layers, then the Locks page, the Disk page and the two lamp pages (the last two; the test tools count from the end). Changes in a burst
are merged: only the last page is built.
reply: OK LAYER n | ERR range
example: layer 26

== key
usage: key <layer> <tile>
summary: Press a tile as if it was touched. It really types on the host!
The tile is sent to the host like a touch would. Power Down and Sleep (tiles of the System and Media pages) are refused (ERR key). Only use it on the Locks
page (Scroll Lock) and on the Wake Up tile of the Media page; never script a loop over a whole page.
reply: OK KEY | ERR key
example: key 26 2

== tap
usage: tap <x> <y>
summary: Touch the screen at x, y (Locks page only).
Refused outside the Locks page (ERR tap), so that a stray coordinate cannot press a key on another page.
reply: OK TAP | ERR tap
example: tap 160 120

== down
usage: down <x> <y>
summary: Hold a touch at x, y until up (Locks page or the header bar only).
For tests of the pressed state: the control under the finger changes colour while the touch is held. Nothing is sent to the host: up first moves
the touch off the control, so no click fires. state shows touch=1 while it is held.
reply: OK DOWN | ERR down
example: down 100 120

== up
usage: up
summary: Release the touch that down is holding.
reply: OK UP | ERR up
example: up

== btn
usage: btn <a|b|c> <down|up>
summary: Press or release a button of the Core2 (A previous page, B Locks, C next page).
down does what the button does and lights its indicator in the header; up puts the indicator out. state shows btn=<bit mask> while held. The CoreS3 has no buttons (ERR btn).
reply: OK BTN DOWN | OK BTN UP | ERR btn
example: btn b down

== clicker
usage: clicker <prev|next|start|blank|end|laser>
summary: Type the key of a presenter button (Core2 only). It really types on the host!
prev is Page Up, next Page Down, start F5, blank B, end Esc and laser Ctrl+L: the keys of every presentation program and every third-party clicker. Needs a Bluetooth host.
reply: OK CLICKER | ERR clicker
example: clicker next

== pointer
usage: pointer [on|off|toggle|click [left|right|middle]|scroll <n>|<setting> <value>|feed <yaw> <pitch>]
summary: The air mouse of the presenter (Core2 only): switch it, tune it, click.
Without arguments it prints the state. The pointer is off until it is switched on. While on, it moves the mouse pointer of the host when the board is turned, and falls asleep by itself after a few seconds of holding still, until it is moved again. Settings: gain 1 to 100 (pixels per degree), idle 0.5 to 30 (seconds still before it sleeps), upright on|off (hold the board upright instead of flat), flipx on|off, flipy on|off. feed pretends the board turns at yaw and pitch degrees per second for 0.6 s (for tests). click presses a mouse button (left by default). scroll turns the vertical wheel n ticks (positive up, negative down).
reply: OK PRESENTER pointer=off|still|moving gain=.. idle=.. | OK POINTER SET | ERR pointer
example: pointer on

== imu
usage: imu <x> <y> <z>
summary: Pretend the gyroscope turns around its three axes (degrees per second) for 0.6 s (Core2 only, for tests).
The pointer uses yaw (z when the board is held flat, y when upright) and pitch (x), so imu 0 0 60 is a turn to the side and imu 40 0 0 a tilt.
reply: OK IMU
example: imu 40 0 60

== mod
usage: mod <ctrl|shift|alt|win|cs|as|meh|hyper|off>
summary: Hold or release a sticky modifier of the mouse page (Core2 only).
The modifiers stay held until you switch them off, so Ctrl+click and Ctrl+scroll work with the mouse. cs is Ctrl+Shift, as Alt+Shift, meh Ctrl+Shift+Alt, hyper Ctrl+Shift+Alt+Win. The same combination again lets it go; off releases all. They are released when the host goes away.
reply: OK MOD <bit mask> | ERR mod
example: mod ctrl

== shot
usage: shot
summary: Screenshot of the screen, 24 bits per pixel.
Prints OK SHOT w h and then w * h * 3 bytes (RGB). The test tools save it as a PNG.
reply: OK SHOT 320 240, then the bytes
example: shot

== perf
usage: perf
summary: How long the last page took to build, render and flush.
reply: OK PERF build_us=... render_us=... flush_us=...
example: perf

== wake
usage: wake
summary: Restart the idle timers: screen and LED bar on again.
reply: OK WAKE
example: wake

== bl
usage: bl <16..255|auto>
summary: Fixed backlight, or auto for the stored dim and off times.
reply: OK BL n | OK BL AUTO | ERR bl
example: bl 100

== leds
usage: leds [off|locks|on]
summary: The LED bar: off (also cuts the 5 V rail of the base), only the host lock state, or the layer colours.
Stored in the settings. Without an argument the settings are shown.
reply: OK LEDS OFF | OK LEDS led=on bright=40 ...
example: leds locks

== set
usage: set [key value]
summary: Show or change the stored settings.
Keys: led (off|locks|on), effect (none|nightrider|breath|rainbow|comet|sparkle|vu), bright 1..120, ledidle minutes, bl 16..255, dim seconds, off seconds,
prefer (usb|ble|both), defaults (any value restores everything). A valid value is stored at once.
reply: OK SET led=on bright=40 ledidle=0 bl=128 dim=60 off=300 prefer=usb effect=none | ERR set
example: set effect nightrider

== prefer
usage: prefer [usb|ble|both]
summary: Which link carries the keys when both are connected.
usb: while USB is mounted keys go over USB only (default). ble: while Bluetooth is connected keys go over Bluetooth only. both: to every connected link.
Without an argument the choice and the connections are shown.
reply: OK PREFER USB | OK PREFER USB usb=1 ble=1
example: prefer ble

== only
usage: only <usb|ble>
summary: Never use the other link, even if the chosen one is down.
reply: OK ONLY USB | OK ONLY BLE | ERR only
example: only usb

== lamps
usage: lamps [reset | grid <cols> <rows> | get <id> | bright <n> | worker on|off]
summary: The LampArray: counters, the lamp grid, one lamp, the bar brightness, the bar worker task.
Without an argument: the counters (reports, lamps set, frames, drawing and latency of the bar and the screen). reset clears them and all lamps. grid sets
the screen lamp grid (at most 60,800 lamps). get shows the colour of one lamp. bright overrides the bar brightness for a test. worker chooses whether the
bar is shown by a task on the second core (default) or by the main loop.
reply: OK LAMPS mode=auto lamps=202 grid=16x12 ... | OK LAMPS GRID c r lamps=n max=n | OK LAMP id r g b i | ERR lamps
example: lamps grid 160 95

== disk
usage: disk [reset | dir | sound on|off]
summary: The Disk demo: the state of the transfer, forget it, list the SD card, mute the modem sounds.
Without an argument the state of the transfer is shown: blocks, speeds, the SHA-256 of the board and of the PC, whether the file was saved. See the manual of
the Disk demo.
reply: OK DISK state=done ok=74 ... | OK DISK RESET | OK DIR, then the files | OK DISK SOUND ON
example: disk dir

== sd
usage: sd
summary: Is there an SD card, which type, how big, how much is used.
The CoreS3 only; the Core2 does not use its card.
reply: OK SD present=1 type=SDHC size_mb=30436 used_mb=1
example: sd

== mic
usage: mic [on|off]
summary: Switch the microphone on or off, or show what it hears.
Without an argument: level and peak (0 to 32767), the dominant frequency in Hz from zero crossings, and the number of buffers. The speaker is off while the
microphone listens (they share the I2S port on the Core2).
reply: OK MIC active=1 level=... peak=... freq=... buffers=... | OK MIC ON
example: mic on

== wave
usage: wave
summary: The last microphone buffer: 512 samples of 16 bits as hex (for tests).
The demo window gets the waveform over the game pad (telem), not from here.
reply: OK WAVE <2048 hex characters>
example: wave

== bar
usage: bar
summary: The colours of the ten bar LEDs as hex (for tests).
The demo window gets them over the game pad (telem), not from here.
reply: OK BAR rrggbb rrggbb ... (ten values)
example: bar

== telem
usage: telem [bar|wave|both|off]
summary: Send the bar colours and/or the microphone waveform to the PC as game pad reports.
The PC reads them from the HID node (report 11, 48 bytes); this command only switches them on or off. The demo window uses it.
reply: OK TELEM BAR | ERR telem
example: telem both
