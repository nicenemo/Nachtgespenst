Nachtgespenst

A night ghost for your keyboard: a Bluetooth LE and USB macro pad built on the M5Stack Core2 and CoreS3. Tap a tile on the touchscreen and the matching key, chord or media command arrives on your computer.

What it does

Nachtgespenst turns an M5Stack touchscreen into a programmable HID device. The screen shows one grid of tiles per layer; tapping a tile sends the matching HID report to the host computer. There are 26 layers and a Locks page, shown on both devices.

  • Keys, chords and media. Keyboard and consumer-control bindings, including Ctrl/Shift/Alt/Win chords and the Meh and Hyper modifier sets.
  • Bluetooth LE and USB. Both boards speak BLE HID (NimBLE). The CoreS3 also enumerates as a USB keyboard and can route keys over USB, BLE, or both.
  • Host feedback. The Locks page shows Caps, Num and Scroll Lock as the host reports them, and the LED bar mirrors them.
  • Colour-coded keys. Keycap colour and legend are drawn in software, so they can differ on every page: tiles are coloured by kind of key and by modifier (Ctrl olive, Alt purple, Win teal), shifted legends are yellow, and each key can show an icon, a caption or a modifier badge. Physical keycaps and their printed legends cannot do that.
  • LED bar. Ten LEDs in the M5GO base show the colour of the current layer.
  • Keymaps as code. Layers are written in C++ in the style of ZMK, using HID shortcut macros generated from the USB HID Usage Tables (kp_A, cp_MUTE, lcs(...), lhyp(...)).
  • Scriptable. A line-based serial protocol lets a test tool switch pages, tap and press tiles, read the state and take screenshots. Every screenshot on this page came from it.

On the Core2 the B button toggles this page; on the CoreS3 tap the title in the bottom bar.

Two interfaces

LVGL (the main branches)

The interface introduced on 12 November 2026: LVGL 9 with a Material icon subset, rounded tiles, captions under icons, modifier badges (Ctrl+Shift, Hyper) and a themed header. It redraws only what changes.

Classic (branch feature/classic-ui)

The current firmware with LVGL removed: every feature of both boards is kept (BLE, USB, LED bars, serial protocol, tests), but the screen is drawn straight onto the display with plain tiles, text labels and arrow shapes, in the spirit of the very first version of the project (a Core2-only flat grid, May 2026). Because the CoreS3 has no hardware buttons, it gets a bottom bar for previous, Locks and next.

How they compare

Both interfaces were built from the same keymap and tested with the same serial test suite, then measured on the boards. A page is "drawn" when it is on the display: LVGL answers LAYER before it renders, so the time is LAYER plus SHOT minus the plain SHOT read-out.

The classic interface is clearly faster to switch pages and uses about a third less memory; LVGL looks richer and leaves room for more widgets. The slow part of LVGL is building a page (creating up to 24 buttons and rasterising icon glyphs at run time), which can be improved with pre-rendered bitmap fonts and reusable tile widgets; that work is on the to-do list.

Testing the LED bars with a webcam

The LED bars are hard to test from software, so the laptop webcam does it. A small JBang tool, tools/LedCam.java, talks to a board over serial and films the result with ffmpeg. Frame differencing uses the Java Vector API; the camera, not the arithmetic, sets the speed.

Finding the CoreS3 bar

The CoreS3 has no documented bar pin, so a test sketch (tools/ledtest, environment cores3) drives the first pixel on every M-Bus and Grove pin in turn, showing red, green and blue, while the camera compares each frame with a dark baseline. The first sweep covered 20 candidate pins: GPIO 5 (M-Bus pin 8) scored 65 against a noise floor of 38 to 41 for every other pin, and the frame showed the bar's base glowing. A second sweep with a better score ranked it first as well. The Core2 bar sits on the same M-Bus pin, which fits.

Checking every layer colour

The tool then cycles LAYER 0 to LAYER 25 on each board and films the bar. The contact sheets below put every frame next to a swatch of the colour the firmware was asked to show. All 26 layers come out with the right hue on both boards. Dark colours (Maroon, Navy, DarkGreen, Indigo) are dimmer, as they should be. Pale colours (PaleGreen, Khaki, Lavender, MistyRose) look blue-white because the camera's white balance shifts when the bar is the only light in the room. The numeric check is weak (the glow is only a few brightness levels), so the verdict comes from looking at the sheets.

Set-up

What you need

  • An M5Stack Core2 and/or CoreS3, ideally with the M5GO base for the LED bar.
  • PlatformIO (the project keeps its own copy under .pio/; see docs/wiki/tooling.md).
  • JBang for the Java tools (header generator, serial tests, camera tool); it downloads the right JDK itself.

Build and flash

git clone https://github.com/nicenemo/nachtgespenst.git
cd Nachtgespenst
pio run -e core2                   # about 12 minutes
pio run -e core2 -t upload         # Core2: resets itself into the bootloader
pio run -e cores3
stty -F /dev/ttyACM0 1200          # CoreS3: ROM download mode, then wait 3 s
pio run -e cores3 -t nobuild -t upload --upload-port /dev/ttyACM0

Pair the board from the host's Bluetooth settings; it advertises as Nachtgespenst-C2 or Nachtgespenst-S3. Over USB the CoreS3 simply appears as a keyboard.

Change the keymap

Layers live in include/Keymap.h as an array of GridLayer (title, bindings, rows, columns, LED colour). Edit, rebuild, flash.

Test it

jbang tools/SerialTest.java --board S3    # 29 checks, including USB and BLE routing
jbang tools/SerialTest.java --board C2    # 11 checks
jbang tools/SerialTest.java --shot shots  # screenshots of every page
jbang tools/LedCam.java colours --port /dev/ttyUSB0 --out cam --crop x0,y0,x1,y1

Regenerate the HID vocabulary

cd tools
jbang FetchHut.jsh          # only when updating to a newer USB HID Usage Tables PDF
jbang GenerateHeaders.jsh
cp -r include/. ../include/

Full instructions, the sandbox set-up used for Claude Code and the decision records are in the docs folder.

How it works

  • Generated HID vocabulary. tools/GenerateHeaders.jsh reads the USB HID Usage Tables (as JSON extracted from the official PDF) and renders FreeMarker templates into usage constants and shortcut macros such as kp_A and cp_MUTE. Nothing in include/hid_* is edited by hand.
  • Binding model. A Binding is a HID page, a usage, a modifier mask and a label. Chord helpers (lcs, lmeh, lhyp) wrap macros the way ZMK does.
  • Keymap and UI. Keymap.h holds the layers; src/ui.cpp draws the current layer, handles touch, mirrors the host LEDs on the bar and dims the backlight after a minute of idleness.
  • HID transports. HIDManager owns BLE (NimBLE) and, on the CoreS3, USB (TinyUSB). Reports go through a non-blocking press queue with release retry; PREFER and ONLY commands choose which transport receives them.
  • Serial protocol. PING, INFO, STATE?, LAYER, TAP, KEY, SHOT, PREFER, ONLY: enough for automated tests and for the screenshots above.

Inspiration: ZMK and the Cornish ZEN keymap

The keymap style comes from the owner's ZMK keyboard firmware work, in particular the configuration for the 42-key Corne-ish Zen (franken-cornish-zen: 31 layers, home-row mods, combos, Unicode, APL and Greek layers), and the header generator follows zmk_unicode_headers, which turns the Unicode database into named C macros the way GenerateHeaders.jsh turns the USB HID Usage Tables into kp_A and cp_MUTE.

Since Claude joined

The project did not start with Claude Code. An earlier version of the firmware was made about a year before, with Gemini in its chat client (the Android app and the browser) and a little help from GitHub Copilot; its keymap style and its header generator come from the owner's ZMK work (see Inspiration). The history of this repository starts on 10 May 2026. On 12 November 2026 the project started working with Claude Code, with a project guide (CLAUDE.md), an overnight plan, and tests that drive the real hardware. The big steps:

  • Before Claude Code (commits of 10 to 14 May 2026)Core2 BLE macro pad, layers and grids, LED bar, and the generator that turns the USB HID specification into C++ headers with a ZMK-style keymap; made with Gemini and some GitHub Copilot.
  • 12 November: a new interface and a second boardLVGL 9 interface with icons and a Locks page; CoreS3 port; USB HID next to BLE; LED bar feedback; the serial protocol, SerialTest and the first screenshots.
  • 13 November: hardeningA review of the HID code led to a non-blocking press queue with release retry, a proper USB-mounted check, BLE security without MITM, atomic LED state and a loop that sleeps instead of spinning.
  • 17 November: project hygieneREADME, licence and third-party notices; decision records for the Claude Code sandbox, a project-local PlatformIO and pinned JDKs; the HUT download split into its own script.
  • 17 and 18 November: routing, LED bars and camera testsSelectable USB/BLE routing with tests for every mode; the CoreS3 LED bar found and verified with a webcam; LedCam and the pin finder; documentation and code comments in British English; this page, a changelog, and the classic interface branch.

The complete list is in the changelog.

The name. Nachtgespenst is inspired by Ben Aaronovitch's Rivers of London series, in particular the novella The October Man, which is set in Germany. The German word for a night ghost suits a small device that sits quietly beside the keyboard and does its work on command.
